# Автообновление APK без браузера

## Канал доставки

Источником является последний публичный GitHub Release репозитория `zigorminsk-debug/pdd`. Приложение загружает фиксированный URL:

```text
https://github.com/zigorminsk-debug/pdd/releases/latest/download/update.json
```

`update.json` содержит `packageName`, `versionCode`, `versionName`, `apkUrl`, `sha256` и примечания к выпуску. URL APK и SHA-256 генерируются в CI из реально собранного и подписанного файла.

## Проверки перед установкой

`UpdateManager` не запускает установщик, если хотя бы одна проверка не прошла:

- описание и APK получены только по HTTPS;
- размер описания ограничен 256 КБ, APK — 150 МБ;
- SHA-256 скачанного файла совпадает с CI-метаданными;
- пакет APK равен `by.pdd.study`;
- `versionCode` APK равен описанию и больше установленного;
- набор SHA-256 сертификатов APK совпадает с установленным приложением;
- APK сохраняется в приватной папке `files/updates`, а не в общедоступном хранилище;
- проверенный файл напрямую копируется в `PackageInstaller.Session` системной службы Android.

`UpdateInstallReceiver` принимает результат конкретной сессии. При `STATUS_PENDING_USER_ACTION` он открывает возвращённый системой экран подтверждения; успех, отмена и ошибки обрабатываются без поиска Activity по `ACTION_VIEW` или `ACTION_INSTALL_PACKAGE`.

## Что видит пользователь

1. Карточку новой версии и изменения.
2. Прогресс загрузки внутри приложения.
3. При первом обновлении — системные настройки разрешения установки из источника.
4. Стандартное подтверждение системного установщика Android.

Браузер не вызывается. **Пользователям версий 1.1.0–1.1.2 нужно один раз установить 1.2.0 вручную из Releases**: старый код зависел от Intent установщика и на MIUI/HyperOS мог завершаться ошибкой. Последующие версии используют системную сессию установки из приложения.

Полностью автоматическая установка без подтверждения доступна только управляемым/системным приложениям, Device Owner или магазину с соответствующей платформенной интеграцией; обычным APK это запрещено Android.

## Выпуск новой версии

1. Увеличить `versionCode` минимум на 1 и обновить `versionName` в `version.properties`.
2. Заполнить `RELEASE_NOTES.md`.
3. Отправить изменения в `main` или `arena/*`: workflow сам сформирует тег `vX.Y.Z` из `versionName`. Также поддерживаются push тега и ручной запуск **Android release** с `publish_release=true` и `release_tag=vX.Y.Z`.
4. Дождаться зелёного workflow и проверить, что Release содержит `app-release.apk`, `app-release.aab`, `update.json`.

Не публиковать Release с тем же `versionCode`: такое обновление не будет предложено. Не менять `applicationId` или подпись — иначе Android и дополнительная проверка приложения отклонят обновление.
